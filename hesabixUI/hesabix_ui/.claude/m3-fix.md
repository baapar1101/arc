قانون `$1` را اصلاح کن. حداکثر `$2` فایل (اگر خالی بود، ۵ تا).

## گام ۱ — وضعیت فعلی

```
!`dart run tool/m3_audit.dart --rule $1 2>&1 | head -80`
```

## گام ۲ — انتخاب دسته

از خروجی بالا، پرتخلف‌ترین فایل‌ها را بردار تا سقف تعداد خواسته‌شده.
**فایل‌های بالای ۱۵۰۰ خط را در این دسته نگذار** — آن‌ها جداگانه و تک‌نفره
انجام می‌شوند. اول فهرست فایل‌های انتخابی را بگو، بعد شروع کن.

## گام ۳ — اصلاح

برای هر فایل:

1. کامل بخوانش. الگوی استفاده را بفهم، نه فقط خط تخلف را.
2. جدول نگاشت `CLAUDE.md` را اعمال کن.
3. اگر `context.*` استفاده کردی، ایمپورت نسبی
   `theme/tokens/extensions.dart` را اضافه کن.
4. **رنگ معنایی را از روی معنا انتخاب کن، نه از روی رنگ.**
   `Colors.green` روی برچسب «پرداخت شده» → `semantic.success`.
   همان `Colors.green` روی نمودار → احتمالاً `colors.tertiary`.
   اگر معنایش از کد معلوم نشد، آن مورد را دست نزن و در گزارش پایانی
   با شمارهٔ خط فهرست کن.
5. رفتار را تغییر نده. فقط ظاهر.

## گام ۴ — تأیید

```bash
flutter analyze <فایل‌های تغییریافته>
dart run tool/m3_audit.dart --rule $1 | head -3
```

هر دو باید تمیز باشند و شمارش پایین آمده باشد.

## گام ۵ — گزارش

بگو: چند مورد در چند فایل اصلاح شد، شمارش قبل و بعد، و هر موردی که
عمداً دست‌نخورده ماند با دلیلش.

کامیت نکن. `--baseline` نزن مگر خواسته شود.
