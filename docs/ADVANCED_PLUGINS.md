# افزونه‌های تخصصی سپیدار

مسیر فضای کاری: `/business/{businessId}/tab0/advanced-plugins`؛ هر افزونه فعال
از بازار افزونه‌ها هم دکمه «مدیریت افزونه» دارد. رکوردها، عملیات، تنظیمات مستقل
و سابقه تغییرات در چهار تب جدا ارائه می‌شوند. دسترسی هر افزونه سه مجوز
`view`، `write` و `settings` دارد؛ مالک کسب‌وکار و مدیر پلتفرم طبق مجوزهای موجود
دسترسی دارند. API عمومی یا عبور از جداسازی کسب‌وکار اضافه نشده است.

| افزونه | امکانات بومی | منابع سپیدار |
| --- | --- | --- |
| `fixed_assets` | دارایی، گروه/طبقه، مکان، اجزای بها؛ پیش‌نمایش و ذخیره برنامه استهلاک خط مستقیم/نزولی، کنترل سقف و همپوشانی | AST: Asset، CostPart، DepreciationRule، AcquisitionReceipt/Item، Depreciation/Item و سوابق جانبی |
| `contracting` | پروژه، قرارداد، اقلام صورت‌وضعیت، کسور صریح، محاسبه خالص و سررسید ضمانت‌نامه | CNT: Project، Contract، Status/Item، Guarantee، Coefficient، Cost، Warranty و سوابق جانبی |
| `payroll_calendar_tax` | تقویم سال/ماه، پرسنل و مانده مرخصی، گروه/جدول/پله‌های مالیات تاریخ‌دار حقوق و عیدی | PAY: PayrollCalendar، DailyHour، Personnel، Leave، TaxGroup، TaxTable/Item |
| `conditional_pricing` | دفتر قیمت و شروط کالا/ارز/واحد/گروه مشتری/نوع فروش/ردیابی/تاریخ/مقدار؛ ارزیابی قیمت با توضیح قاعده | SLS: PriceNote/Item، PriceNoteItemDiscount، SaleType، CustomerGrouping |
| `inventory_trace_cost` | دسته/بچ ردیابی، اتصال لایه‌ها و خروج‌ها به حواله بومی، گزارش FIFO و برآورد با بهای نامعلوم صریح | INV: TracingCategory، Tracing، InventoryReceiptItem، InventoryDeliveryItem، PricingPeriod و Voucher |

## همگام‌سازی

در تنظیمات هر افزونه، «فعال» و «همگام‌سازی سپیدار» جدا هستند. پیش‌نیاز:
مجوز فعال افزونه، اتصال سپیدار فعال، واردسازی کامل، تبدیل بومی و پل افزونه‌ها؛
ردیابی انبار به تبدیل عملیات انبار نیز نیاز دارد. همان چرخه زمان‌بندی و قفل
تراکنشی اتصال سپیدار اجرا می‌شود؛ شغل زمان‌بندی موازی دیگری اضافه نشده است.

هویت رکورد از دیتابیس + جدول + شناسه مبدأ ساخته می‌شود. تغییرات با hash تشخیص
داده شده، حذف مبدأ بایگانی می‌شود و بازگشت همان رکورد همان شناسه بومی را نگه
می‌دارد. مراجع نامعتبر اجرای تراکنش را متوقف می‌کنند. رکورد سپیدار در UI/API
قابل بازنویسی محلی نیست؛ رکوردهای محلی مستقل با کنترل نسخه قابل مدیریت‌اند.

واردسازی، دفتر اصلی ACC یا موجودی/بهای منتقل‌شده قبلی را مجدداً ثبت نمی‌کند.
هیچ خرید، برداشت کیف پول، پیامک، عملیات بانکی یا ثبت خودکار سند مالی ندارد.

## قواعد و محدودیت‌های صریح

- استهلاک یک پیش‌نویس عملیاتی است، نه موتور کامل ثبت مالی AST. شرایط ویژه سقف
  ارزش دفتری و دوره‌های دارای استهلاک قبلی بدون بررسی مجدد محاسبه نمی‌شوند.
- صورت‌وضعیت بر اساس مقادیر تأییدشده یا مقادیر و نرخ محلی محاسبه می‌شود؛
  ضرایب و نرخ قانونی حدس زده نمی‌شوند. گردش تأیید قرارداد/بانک شبیه‌سازی نشده است.
- مالیات جاری فقط با جدول معتبر در تاریخ، گروه و نوع درآمد مشخص و تأیید نسخه
  دقیق جدول و پله‌ها قابل محاسبه است. تغییر جدول/پله، تأیید قبلی را نامعتبر
  می‌کند. تنظیم `auto_apply_tax` به‌صورت پیش‌فرض خاموش است. در صورت فعال‌سازی،
  قواعد تأییدشده حقوق در محاسبه بومی payroll استفاده و نسخه قواعد در run ثبت
  می‌شود؛ بیمه خودکار فعال نمی‌شود. عیدی پیش‌نمایش جدا دارد. تقویم و واحد زمان
  مبدأ بدون تبدیل حدسی حفظ می‌شوند؛ مانده مرخصی snapshot است، نه جمع تغییرات.
- پیشنهاد قیمت فاکتور موجود را خودکار تغییر نمی‌دهد. تعارض قواعد خطاست.
  تخفیف/افزوده همزمان مبدأ نیازمند تعیین صریح ترتیب محاسبه در تنظیمات است.
  پنجره تخفیف زمان‌بندی‌شده فعال بدون بررسی صریح به قیمت نهایی حدسی تبدیل نمی‌شود.
- FIFO گزارش/برآورد لایه‌ای است، نه بازقیمت‌گذاری اسناد صادرشده. لایه‌ها به سال
  مالی و حواله posted محدود و موجودی بومی به‌صورت تجمعی تا تاریخ محاسبه می‌شود.
  بهای نامعلوم، خروج بدون لایه و پیوند نامعتبر صریح‌اند؛ برآورد نامطمئن رد می‌شود.
- جدول خالی منبع داده فرضی ایجاد نمی‌کند. برای نمونه، خالی بودن دارایی/قرارداد/
  پرسنل در دیتابیس فعلی به معنی خرابی صفحه مدیریت نیست.

## API و آزمون

پیشوند: `/api/v1/advanced-plugins/business/{business_id}`. مسیرهای `/settings`،
`/records`، `/references/{type}`، `/operations/{action}` و `/audit` زیر کد افزونه
قرار دارند. فهرست رکورد صفحه‌بندی‌شده، ویرایش دارای revision، فیلدهای ورودی
دارای allowlist، اعداد محدود و Decimal، و مراجع بین کسب‌وکارها مسدود هستند.

تست‌های `tests/test_advanced_plugins.py` همراه تست‌های تبدیل بومی، انبار/تسویه،
حقوق و دسترسی اجرا می‌شوند. آزمون‌های مالی فقط روی دیتابیس جداگانه با پسوند
`_sepidar_test` انجام می‌شوند. پذیرش production شامل dry-run با rollback،
دو اجرای تبدیل با هویت ثابت، مقایسه hash دفتر/موجودی/کیف پول و یک چرخه لایو است.

## استقرار

مهاجرت دقیق: `20261023_000004_advanced_addons` (پس از مهاجرت پل افزونه‌ها).
ساختار سه جدول `advanced_plugin_settings`، `advanced_plugin_records` و
`advanced_plugin_audits` و پنج هویت بازار اضافه می‌شود. تعرفه عمومی یا فعال‌سازی
برای سایر کسب‌وکارها خودکار نیست. مجوز آزمایش حساب سپیدار با تخصیص مدیریتی،
plan داخلی غیرفعال برای فروش و بدون سفارش/صورتحساب/تراکنش کیف پول داده می‌شود.

به‌روزرسانی API بعد از پایان چرخه در حال اجرای سپیدار انجام می‌شود. UI با
نگه‌داشتن فایل‌های hash قدیمی و جایگزینی index در آخر منتشر می‌شود. rollback
کد/ورودی UI با حفظ جداول افزایشی و داده‌ها ممکن است؛ downgrade جداول در سرور
تولید اجرا نشود چون رکوردهای عملیاتی و تاریخچه را حذف می‌کند.
