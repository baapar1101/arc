# برنامه استاندارد افزونه «ورود لایو اطلاعات از سپیدار»

## هدف و مرز ایمنی

افزونه یک اتصال **فقط‌خواندنی** به SQL Server سپیدار برقرار می‌کند و نسخه‌ای قابل‌ردیابی از داده‌ها را در PostgreSQL حسابیکس نگه می‌دارد. هیچ `INSERT`، `UPDATE` یا `DELETE` روی سپیدار انجام نمی‌شود. اطلاعات اتصال رمزنگاری می‌شوند و رمز عبور هرگز در پاسخ API یا Git ثبت نمی‌شود.

## معماری

1. تنظیم اتصال برای هر کسب‌وکار: سرور، پورت، دیتابیس، کاربر، رمز، دوره اجرا، batch size و فیلتر schema/table.
2. کشف ساختار از `INFORMATION_SCHEMA`: جدول‌ها، ستون‌ها و کلید اصلی بدون اعتماد به نام ورودی کاربر.
3. Snapshot خام و کامل: هر رکورد سپیدار با کلید پایدار، payload JSON، hash محتوا و زمان مشاهده در حسابیکس ذخیره می‌شود.
4. همگام‌سازی idempotent: اجرای مجدد رکورد تکراری نمی‌سازد؛ رکورد تغییرکرده به‌روزرسانی می‌شود.
5. اجرای لایو: worker داخلی فقط تنظیمات فعال و موعدرسیده را اجرا می‌کند و به‌کمک lock پایگاه‌داده از اجرای همزمان جلوگیری می‌شود.
6. مشاهده‌پذیری: تاریخچه اجرا، تعداد جدول/رکورد، مدت، خطا و آخرین موفقیت ثبت می‌شود.

## فازهای انتقال

- فاز ۱ (این پیاده‌سازی): mirror کامل و امن تمام جدول‌های انتخاب‌شده؛ مناسب حفظ همه اطلاعات و تحلیل/نگاشت بعدی.
- فاز ۲: نگاشت موجودیت‌های اصلی به مدل بومی حسابیکس (اشخاص، کالا، انبار، فاکتور، دریافت/پرداخت، سند حسابداری) با جدول mapping و سیاست تعارض قابل انتخاب.
- فاز ۳: CDC به‌کمک Change Tracking/rowversion در صورت فعال بودن روی SQL Server و reconciliation زمان‌بندی‌شده.

## کنترل کیفیت و rollback

- تست اتصال قبل از فعال‌سازی، محدودیت batch، timeout و ثبت خطای بدون secret.
- هر row دارای `source_key` و `content_hash` است؛ sync قابل تکرار و قابل audit است.
- خاموش‌کردن افزونه اجرای آینده را متوقف می‌کند و داده mirror را حذف نمی‌کند.
- حذف داده فقط با عملیات مدیریتی جداگانه و صریح انجام خواهد شد.

## معیار پذیرش

- رمز عبور در API بازگردانده نشود.
- اتصال read-only و catalog discovery موفق باشد.
- sync دوم روی داده بدون تغییر، duplicate نسازد.
- خطای یک جدول کل run را قابل تشخیص کند.
- صفحه تنظیمات امکان تست اتصال، کشف جدول‌ها، ذخیره تنظیمات، اجرای دستی و مشاهده وضعیت را بدهد.
