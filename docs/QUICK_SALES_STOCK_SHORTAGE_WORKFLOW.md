# گردش‌کار کسری موجودی در فروش سریع

## هدف

این قابلیت برای حالتی است که کالا به‌صورت فیزیکی در انبار وجود دارد اما موجودی سیستمی به علت ثبت‌نشدن یا اشتباه یک رویداد قبلی کافی نیست. رفتار پیش‌فرض سامانه همچنان جلوگیری از ثبت فاکتور دارای کسری است. امکان عبور فقط برای همان فاکتور فروش سریع، با تنظیم فعال، مجوز مستقل و ثبت علت فراهم می‌شود.

این قابلیت سیاست عمومی موجودی منفی کسب‌وکار را تغییر نمی‌دهد و روی انتقال بین انبارها اثر ندارد. کالای یونیک/سریالی نیز از مجوز یک‌باره مستثناست.

## رفتار کاربر در فروش سریع

API همهٔ اقلام دارای کسری را در یک پاسخ `409 / INSUFFICIENT_STOCK` برمی‌گرداند. دیالوگ فروش سریع نام کالا، انبار، موجودی قابل استفاده و مقدار موردنیاز را نمایش می‌دهد و این انتخاب‌ها را ارائه می‌کند:

1. **انصراف**: فاکتور و موجودی تغییری نمی‌کند.
2. **پارک فروش**: فروش جاری در فهرست فروش‌های پارک‌شده نگهداری و یک فروش خالی باز می‌شود.
3. **اصلاح موجودی**: فقط برای موجودی فیزیکیِ مازاد با منشأ نامشخص است. کاربر باید این وضعیت را صریحاً تأیید کند. سامانه سند «کالای درآمدشده» را با تاریخ واقعی روز کشف، مقدار کسری و بهای خرید پایه کالا ثبت و قطعی می‌کند؛ سپس ثبت فاکتور را دوباره انجام می‌دهد.
4. **ثبت با موجودی منفی**: کاربر علت را انتخاب می‌کند و فاکتور فقط برای کالاهای فله ثبت می‌شود. یک پرونده مغایرت باز و به فاکتور و حواله انبار پیوند داده می‌شود.

اگر خرید، انتقال یا موجودی اول دوره از قلم افتاده است، کاربر نباید گزینه «اصلاح موجودی» را انتخاب کند. در آن حالت سند اصلی خرید، انتقال یا افتتاحیه باید با تاریخ واقعی خودش ثبت شود.

## تنظیم و مجوزها

- کلید `quick_sales_settings.enable_stock_shortage_override` به‌صورت پیش‌فرض `false` است.
- فعال‌سازی از «تنظیمات فروش سریع ← تنظیمات موجودی ← گردش‌کار کسری موجودی» انجام می‌شود.
- ثبت یک‌باره موجودی منفی به مجوز `inventory.negative_stock_override` نیاز دارد.
- اصلاح فوری با کالای درآمدشده به مجوزهای `goods_expense_income.add` و `goods_expense_income.post` نیاز دارد.
- مشاهده پرونده‌های مغایرت به `inventory.view` نیاز دارد.
- مالک کسب‌وکار و مدیر کل طبق منطق عمومی مجوزها دسترسی دارند.

## قرارداد API

پاسخ کسری نمونه:

```json
{
  "success": false,
  "error": {
    "code": "INSUFFICIENT_STOCK",
    "message": "موجودی کافی برای یک یا چند کالای فاکتور وجود ندارد",
    "details": {
      "shortages": [
        {
          "product_id": 10,
          "product_name": "کالای نمونه",
          "product_code": "A-10",
          "warehouse_id": 3,
          "warehouse_name": "انبار اصلی",
          "inventory_mode": "bulk",
          "available_quantity": 0,
          "requested_quantity": 1,
          "shortage_quantity": 1
        }
      ]
    }
  }
}
```

در تلاش دوم، کلاینت `stock_override` را در ریشه درخواست فاکتور می‌فرستد:

```json
{
  "stock_override": {
    "reason_code": "physical_stock_exists",
    "reason_note": "یک عدد در قفسه شمارش شد",
    "request_token": "qs-4952-unique-token"
  }
}
```

سرور هر مقدار `_stock_override` ارسالی در `extra_info` را حذف می‌کند. علامت داخلی مجازبودن فقط پس از کنترل موارد زیر ساخته می‌شود:

- درخواست واقعاً فروش سریع باشد (`extra_info.quick_sale == true`)
- قابلیت در تنظیمات فروش سریع فعال باشد
- کاربر مجوز `inventory.negative_stock_override` داشته باشد
- علت معتبر و شناسه درخواست موجود باشد
- هیچ‌کدام از کسری‌ها کالای یونیک نباشد

APIهای رسیدگی:

- `GET /api/v1/businesses/{business_id}/quick-sales/stock-discrepancies?status=open`
- `POST /api/v1/businesses/{business_id}/quick-sales/stock-corrections`
- `POST /api/v1/businesses/{business_id}/quick-sales/stock-discrepancies/{case_id}/resolve`

## رسیدگی پس از ثبت موجودی منفی

پرونده‌های ایجادشده از مسیر «انبار ← مغایرت‌های موجودی فروش سریع» قابل مشاهده‌اند. فیلتر صفحه پرونده‌های باز، رفع‌شده یا همه موارد را نشان می‌دهد و اطلاعات فاکتور، علت، کالا، انبار و مقدار کسری را نمایش می‌دهد.

برای یک پرونده باز، گزینه «رفع مغایرت» را انتخاب کنید، تاریخ واقعی کشف اصلاح را وارد کنید و موجودی فیزیکی با منشأ نامشخص را تأیید کنید. بهای واحد به‌صورت پیش‌فرض از قیمت خرید پایه کالا گرفته می‌شود و در صورت فعال‌بودن تغییر دستی بها و داشتن مجوز مربوط، قابل جایگزینی است. ثبت نهایی سند قطعی «کالای درآمدشده» را ایجاد می‌کند، پرونده را می‌بندد و بهای تمام‌شده و سود ناخالص ردیف فروش را بازشناسی می‌کند.

اگر منشأ کسری یک خرید، انتقال یا موجودی اول دوره ثبت‌نشده است، از این عملیات استفاده نکنید و سند اصلی را با تاریخ واقعی همان رویداد ثبت کنید.

## ردپای حسابرسی

جدول `inventory_discrepancy_cases` اطلاعات فاکتور، حواله، کاربر ثبت‌کننده، علت، وضعیت و سند رفع مغایرت را نگه می‌دارد. جدول `inventory_discrepancy_lines` مقدار موجود، مقدار درخواست‌شده، کسری و مقدار رفع‌شده را برای هر کالا و انبار ثبت می‌کند.

`request_token` در محدوده کسب‌وکار یکتا است. شناسه پرونده داخل `Document.extra_info._stock_override.discrepancy_case_id` ذخیره می‌شود. رفع مغایرت نیز روی ردیف فاکتور در `stock_shortage_resolutions` ثبت می‌شود.

## تاریخ و بهای تمام‌شده

تاریخ اصلاح، تاریخ واقعی کشف و ثبت اصلاح است و به روز قبل از فروش جعل نمی‌شود. حوالهٔ ورودی کالای درآمدشده با `unit_cost` وارد جریان تحلیلی FIFO/LIFO می‌شود. در رفع پرونده پس از فروش، مقدار و بهای اصلاح به ردیف فروش تخصیص داده و دفتر بهای تمام‌شده و سود ناخالص همان ردیف بازشناسی می‌شود.

این طراحی زنجیره زمانی انبار را حفظ می‌کند: رویداد گذشته فقط وقتی با تاریخ گذشته ثبت می‌شود که واقعاً سند اصلیِ گذشته، مانند خرید یا انتقال، بازیابی و ثبت شده باشد.

## مهاجرت و راه‌اندازی

مهاجرت زیر باید پیش از فعال‌کردن گزینه اجرا شود:

```bash
cd hesabixAPI
.venv/bin/alembic upgrade head
```

مهاجرت `20261012_000001_quick_sales_stock_shortage` ستون تنظیمات و دو جدول پرونده مغایرت را ایجاد می‌کند. پس از مهاجرت، API باید reload شود. فرانت در حالت توسعه با hot restart و در نسخه وب release با build/release معمول پروژه به‌روز می‌شود.

## سناریوهای پذیرش

1. با دو کالای فله دارای کسری، پاسخ یک‌باره شامل هر دو کالا باشد.
2. بدون فعال‌بودن تنظیم یا بدون مجوز، درخواست override با `403` رد شود.
3. مقدار `_stock_override` جعلی در `extra_info` هیچ اثری نداشته باشد.
4. کالای یونیک حتی با مجوز override ثبت نشود.
5. ثبت منفی، فاکتور و حواله قطعی و یک پرونده باز بسازد.
6. اصلاح موجودی، سند کالای درآمدشده را با تاریخ روز ایجاد کند و ثبت فاکتور در تلاش بعدی موفق شود.
7. رفع پرونده، سند اصلاح را پیوند دهد، پرونده را `resolved` کند و بهای تمام‌شده ردیف فروش را بازشناسی کند.
8. انتقال انبار همچنان با کنترل مثبت موجودی اجرا شود.
