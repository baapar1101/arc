# پذیرش سه افزونه با کدینگ سپیدار — ۲۰۲۶-۱۰-۲۳

این تغییر، تست‌ها و نتیجهٔ تنظیمات بررسی‌شده را ثبت می‌کند؛ نه migration
فعال‌ساز حساب‌ها، نه عملیات صدور و نه تغییری در UI اجرایی. تنظیمات کسب‌وکار
در دیتابیس باقی می‌مانند و با `git pull` بازنویسی یا seed نمی‌شوند.

## وضعیت مورد انتظار کسب‌وکار سپیدار

منبع فقط `Sepidar01` است؛ آرشیو قدیمی در این پذیرش وارد نمی‌شود.

| افزونه | حساب‌های معین سپیدار | وضعیت |
| --- | --- | --- |
| تعدیل مستقل مالیات حقوق | حقوق پرداختنی `211101` / مالیات حقوق کارکنان `211128` | افزونه، لایو و امکان پیش‌نویس فعال |
| تعدیل مستقل قیمت فروش داخلی | دریافتنی `111201`، فروش داخلی `411001`، مالیات طبق تنظیم مبدأ `211130` | افزونه، لایو و امکان پیش‌نویس فعال |
| تعدیل مستقل بهای خروج | بهای فروش داخلی `511001` / موجودی `111501` | افزونه، لایو و امکان پیش‌نویس فعال |
| پیمانکاری | انتخاب نشده؛ حساب‌های مبدأ خالی و جهت قرارداد نامشخص | خود افزونه، لایو و ثبت مالی خاموش |
| دارایی ثابت | انتخاب نشده؛ حساب استهلاک به نوع دارایی وابسته است | خود افزونه، لایو و ثبت مالی خاموش |

نگاشت انبار مربوط به مرکزی/کارمانیا است، نه ضایعات. نگاشت فروش مربوط به
کالای داخلی است، نه خدمات یا صادرات. مبلغ تعدیل فقط اختلاف مستند است؛
نرخ مالیات، سال مالی، نوع دارایی یا جهت پیمان حدس زده نمی‌شود.

خاموش‌کردن دو افزونه، رکوردهای قبلی آن‌ها را حذف نکرده است. در پذیرش اولیه
فقط ثبت مالی خاموش بود؛ به درخواست کاربر، `enabled` و `sync_enabled` خود
آن دو نیز خاموش شدند. سه افزونهٔ دیگر دست‌نخورده فعال ماندند.

## نتیجهٔ آزمون‌ها

- روی کد پایهٔ `9a83a299`: مجموعهٔ اصلی ۱۵۸ تست موفق در ۲۵۸٫۲۱ ثانیه.
- تست تکمیلی `tests/test_configured_posting_acceptance.py`: بیست تست موفق در
  ۸۲٫۶۷ ثانیه؛ جمع نهایی ۱۷۸ تست موفق، بدون تست ناموفق در اجرای نهایی.
- تست‌های جدید با دادهٔ ساختگیِ مجزا همان نگاشت حساب‌ها را بررسی می‌کنند:
  افزایش/کاهش، توازن، مالیات صریح تعدیل قیمت، پیش‌نویس بدون سند، تکرار
  معنایی با رکورد جدید، حفاظت مبدأ سپیدار، حساب/ارز/سال مالی و نسخهٔ تغییرکرده.
- API برای هر سه افزونه: بدون ورود 401، کسب‌وکار دیگر و کارمند بدون مجوز
  تأیید 403، تأیید مالک با `confirmed` حذف‌شده/false/null برابر 409 و بدون
  درج سند. انتظار اولیهٔ یک تست 400 بود؛ با قرارداد واقعی 409 اصلاح شد،
  نه اینکه رفتار برنامه برای گذراندن تست تغییر کند.
- مجموعهٔ قبلی همچنین صدور تأییدشده، درخواست تأیید هم‌زمان، rollback کامل
  خطا، برگشت معکوس و جلوگیری از دست‌کاری سند صادرشده را پوشش می‌دهد.
- هشدارهای deprecation موجود پروژه مانع موفقیت آزمون‌ها نشدند.

تمام تست‌های صدور فقط در دیتابیس disposable با پسوند `_sepidar_test`
انجام شدند؛ هیچ `approve` یا `reverse` روی حساب واقعی اجرا نشد.

## کنترل واقعی مرورگر و سرور

فرم و حساب‌های هر سه تب مالی در مرورگر با پاسخ سرور مطابقت داشتند؛ هیچ
پیش‌نویس یا سند واقعی وجود نداشت و پیام «همگام‌سازی به‌تنهایی سند نمی‌سازد»
نمایش داده شد. سوییچ‌های افزونه و لایو برای پیمانکاری و دارایی ثابت خاموش
بودند. خطای مرورگر مشاهده نشد. هر دو سرویس API فعال و مسیر واقعی
`/api/v1/health` سالم بود؛ خواندن API مالی بدون ورود 401 بازگرداند.

چرخهٔ لایو شمارهٔ ۴۴، پیش از توقف دو افزونه: ۳۷۹/۳۷۹ جدول، صفر تغییر، موفق
در `2026-10-23 18:51:11.480037 UTC`، بدون خطای مبدأ یا تبدیل بومی.

کنترل نهایی اولیه در `2026-10-23T18:57:37.140559Z`: تعداد ردیف دفتر ۱۳٬۸۸۱؛
hash محتوای دفتر و کیف پول قبل/بعد برابر؛ صفر رویداد محلی واجد شرایط، صفر
پیش‌نویس و صفر سند/برگشت افزونه. دادهٔ مالی واقعی برای تست ساخته نشد.

## اجرای مجدد ایمن

از ریشهٔ `hesabixAPI` و با PostgreSQL disposable مجزا:

```bash
# SEPIDAR_TEST_DSN را از محیط امن، فقط به دیتابیس disposable تنظیم کنید.
PYTHONPATH=. python scripts/run_configured_posting_acceptance.py
```

runner به DSN صریح نیاز دارد، پسوند `_sepidar_test` را کنترل می‌کند و
دیتابیس برنامه را نمی‌پذیرد. هیچ DSN، رمز یا توکن در مخزن ثبت نشده است.
fixture جداول آزمون را می‌سازد و حذف می‌کند؛ هرگز از دیتابیس دارای دادهٔ
واقعی یا تست مشترک در حال اجرا استفاده نکنید.

روی production فقط کنترل بدون تغییر اجرا شود:

```bash
PYTHONPATH=. .venv/bin/python scripts/verify_sepidar_posting_release.py \
  --business-id 4955 --expect-no-postings
```

این کنترل تراکنش `READ ONLY` دارد؛ هیچ تنظیم، پیش‌نویس، تأیید یا سندی
نمی‌سازد. خروجی `settings` و `invariants` قبل و بعد انتشار باید یکسان بماند.
اگر کاربر در این فاصله سند واقعی ایجاد کرده، کنترل متوقف می‌شود؛ نباید
برای عبور از آن سند یا سابقه‌ای حذف شود. موفقیت تست مجوز صدور واقعی نیست.

گیت فعلی، مجوز مدیر/مالک و تأیید صریح نسخهٔ پیش‌نویس را الزام می‌کند؛ قفل
جدیدِ تأییدکنندهٔ انحصاری به یک user_id اضافه نشده است. عامل بدون تأیید
کاربر هیچ سند واقعی صادر نمی‌کند. هیچ مسیر تأیید خودکار در انتشار وجود ندارد.
